# Pharma Khaato 2.5.1 review candidate

This candidate fixes backup rejection of recognized historical migration records, prevents failed print jobs being reported as successful, and isolates bundled Linux GIO libraries from incompatible host modules.

It also contains the audited financial/recovery work: exact monetary storage with historical reconciliation, stronger restore authority and host exclusivity, bounded LAN sessions/connections, staff deactivation, explicit lot selection, non-blocking settings, and an installed owner-recovery utility. Prescription-required products are blocked pending an approved verification workflow.

This is not a production approval. Test only on disposable or approved copies until the exact installer passes dependency/license review, supported OS install/update/rollback checks, LAN fault tests, historical balance reconciliation, device acceptance and an owner-supervised pilot.

Before any upgrade, make and verify an off-device recovery copy. A genuine historical fraction below a paisa stops the new money migration for explicit reconciliation; it is not silently rounded away. Rollback requires the matching old application and pre-upgrade database/configuration together. Do not install an older executable against a newer database.

See [implementation status](../../IMPLEMENTATION_STATUS.md) for current evidence and remaining gates. No automatic production update, merge or deployment is authorized by this candidate.
