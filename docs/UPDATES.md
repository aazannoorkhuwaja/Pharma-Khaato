# Optional updates for an offline POS

Sales, inventory, customer credit and cash work without internet. Shared counters still require their local shop network and main computer. Internet is used only for the optional release check described here; this feature does not upload shop records, customers, sales or backups.

## Operator experience

- After sign-in, an interactive app checks in a background worker after approximately 12 seconds. If internet is unavailable, nothing interrupts the cashier; checks retry about every five minutes. Successful checks are limited to once per 24 hours on that workstation.
- A notice is shown only for a newer stable release with the matching Windows Setup or Linux archive and its checksum attached. It waits for a clear cart, no pending submitted bill, and no open modal dialog. It shows the installed/new version and the publisher's release notes, including fixes.
- **Later** leaves the app running. The same version is not automatically prompted again during that window's lifetime. **Open Update Download** opens the official GitHub release page in the default browser. It does not download or execute an installer automatically, close the POS, migrate data or restart Windows.
- Finish/hold work, confirm pending operations, make a backup and coordinate all shared counters before installing. Follow the Windows getting-started guide. Never update the main computer while other counters are working.
- Open **About Pharma Khaato → Check for Updates** for a manual check. The same dialog has a checkbox to disable automatic checks entirely on this computer. Manual checks still work when automatic checks are off. Losing internet never disables the POS.

GitHub receives ordinary connection metadata such as the public IP address and installed app version in the User-Agent. No business data is sent. Checks use HTTPS with normal certificate verification and a short timeout. Offscreen/headless test runs do not start automatic network checks.

## Publishing a version that the app can discover

The source repository is `aazannoorkhuwaja/Pharma-Khaato`. Update metadata comes only from its published GitHub Releases. Drafts and prereleases are ignored. Release-page URLs are constructed from a validated numeric version tag; arbitrary URLs supplied in metadata are not opened.

1. Update `ApplicationSettings.APP_VERSION`, the installer version default and changelog together. Use a stable numeric tag such as `v2.4.1`.
2. Run the source tests and the Windows/Linux release workflow on the exact proposed revision. Review installed-app, reinstall and data-retention results and complete any applicable physical-device checks.
3. Follow [RELEASING.md](RELEASING.md) to build both platforms and create the draft for the accepted tag. Write plain-language notes explaining what was fixed, any changed operator steps, known issues and upgrade precautions. Notes must not contain customer records.
4. Confirm the draft includes both Linux packages and the verified `Pharma-Khaato-2.4.1-Setup-Windows-x64.exe` and `Pharma-Khaato-2.4.1-Setup-Windows-x64.exe.sha256` (replace the version consistently). Preserve the checksum generated by the build. A tag or workflow artifact alone does not make an update discoverable.
5. Publish the reviewed stable release. This is an explicit maintainer action: the tag workflow prepares a draft only and does not publish a stable release automatically.

Automatic download, installer execution, silent background replacement, mandatory updates and automatic rollback are not implemented. Code signing remains a release requirement before broad public Windows distribution. An unsigned pharmacy pilot must be identified clearly and supplied through a trusted channel with its checksum.
