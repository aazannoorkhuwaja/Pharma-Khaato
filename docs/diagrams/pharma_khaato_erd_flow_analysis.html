ERD vs implementation gaps
In ERD, missing in code
• Stock entity (ERD annotation) — no Stock table in SQL
• id_card_number as FK works but is a VARCHAR PK (fragile)
• Employee–Customer direct relation (ERD note) — not implemented
• Receipt.number_of_items vs Purchase.number_of_products redundancy
In code, not in ERD
• Invoice file generated on disk (not in DB)
• Auto-start MySQL OS-level logic
• SHA-256 password hashing (ERD shows plain password field)
• Batch consolidation logic (duplicate batch_id merge in cart)
SQL schema issues
• INSERT data uses integer customer IDs — schema is VARCHAR(20) CNIC
• Email_Address is LONGTEXT (should be VARCHAR)
• Supplier.phone_number VARCHAR(15) — too short for intl. numbers
• Products.formula VARCHAR(255) — insufficient for long formulas
Business logic gaps
• No return/refund flow anywhere
• No role-based access (admin vs salesman)
• No audit trail for stock edits
• Tax rate not configurable — hardcoded 10%
